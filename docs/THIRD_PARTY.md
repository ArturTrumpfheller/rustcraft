# Third-party dependencies and asset policy

This file is a policy for future contributions, not an inventory of currently included packages.

- Record dependency name, version or commit, upstream URL, SPDX identifier, and required notices when adding third-party code.
- Prefer MIT, Apache-2.0 or other compatible permissive dependencies where feasible; review copyleft packages before copying or linking code.
- Preserve required copyright, attribution, NOTICE, and license files.
- Independently implement Minecraft-inspired mechanics; do not copy proprietary game source, textures, sounds, logos, or branding.
- For each asset, document its author, origin, license and any attribution obligations. Code dual-licensing does not grant rights to separately licensed assets.
- Before public release, audit dependencies, vendored material, assets, and the complete Git history for restricted material or secrets.
- Keep the project private until the release-readiness and licensing review has been completed.

Project-created code and documentation: MIT OR Apache-2.0, at the recipient's option. See the root LICENSE-MIT and LICENSE-APACHE files.
